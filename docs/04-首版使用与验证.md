# 首版使用与验证（v0.1）

验收状态按证据标记为**通过**、**失败**或**未执行**。各项的环境、样本和限制见对应记录。

## 版本与环境

共享 agent 凭据属于本机服务范围，而不是工具身份：不同工具使用同一凭据，写会话授权和代次用于阻止旧会话写回，不隔离同一系统用户下的恶意进程。新服务写出的 CLI 凭据绑定监听端口；新 CLI 在端口不一致或凭据损坏时拒绝发出请求，历史随机令牌格式仍可读取但不具备端口绑定。端口匹配不能证明服务进程身份，新旧服务与 CLI 应一起更新。

- 版本：0.0.1（开发中；未发布 npm、无 Release）。
- 支持 Windows x64、Git、Node.js `>=24.22.3 <25`。本轮实测 Windows 11 x64、Node.js 24.22.3。

## 容量与性能

**本版支持范围。** 默认每项目 20 MiB（20,971,520 B）。单个受管理附件上限 5 MiB。恢复入口接受格式 v1、记录结构 v16、v17、v18，ZIP 请求体最多 64 MiB，历史包最多 65,535 项。激活前逐文件校验长度及摘要，校验记录引用，再按本机预算核对迁移后的项目用量。目的数据目录已有同标识项目时拒绝合并。当前结构的 Windows 单项目串行满额往返已实测；旧结构兼容依据迁移和拒绝路径测试。

- 默认每项目记录预算 20 MiB（含附件字节、活跃会话预留）；80% 起预警；按记录字节预算超限的写入以 413 原子拒绝，操作状态（导出/恢复）不占预算。每项目新增不同附件最多 9,998 个，超限返回 413 `ATTACHMENT_COUNT_EXCEEDED`；重复内容与已成功请求的重放不受该数量上限阻挡，仍受字节预算及附件完整性校验。
- 默认 20 MiB 预算的隔离样本：4 个不同的 4.5 MiB 合成附件，项目用量 18,877,710 字节、ZIP 18,880,008 字节；导出、同限恢复、再导出后逐项内容一致，超预算新增被拒。本机 Windows x64、Node 24.22.3，`npx vitest run tests/integration/recovery-nearlimit.test.ts --reporter=verbose --silent=false` 的一次测量中该场景耗时 953 ms，测试进程累计最大 RSS 为 295,004 KiB。耗时包括临时仓库和实例创建；RSS 包含测试框架、两个实例及测试持有的缓冲区，不代表独立服务的峰值，也不是性能承诺。后续默认预算安装包实测见[六组容量记录](agents/2026-11-28-k19-capacity.md)。
- 处置历史按变更一次读取并按条件分组。内存 SQLite 的单次合成样本（100 条件、1 万条处置）中，逐条件查询约 49 ms，一次查询及分组约 8 ms；这是查询样本而非端到端性能或生产负载承诺。
- 开发阶段只读历史使用独立查询，不执行候选证据附件健康检查；集成测试确认其历史内容与审阅视图一致、未登录请求被拒绝，正式审阅仍执行附件检查。
- 正式审阅读取在单次请求内合并同一附件的健康检查；集成测试覆盖多个条件和决定共用附件、随后修改文件，确认下一次请求重新检查并识别损坏。预览和确认仍独立重新校验，不能据此声称读取期间文件不会变化。
- 文件项边界：用户确认新写入上限为 9,998 个不同附件，历史 ZIP 解析兼容最多 65,535 个文件项；后者仍受 64 MiB 请求体、本地预算与格式校验限制。隔离实测批量写入测试数据库并创建真实小附件：9,998 个附件生成 10,000 项 ZIP，19,999 个历史附件生成 20,001 项 ZIP，两者均完成导出、恢复和再导出，记录投影及全部附件内容一致。后者项目用量为 12,340,324 / 20,971,520 字节；两组样本从构造到完成约 114 秒，包含测试实例和文件创建，未计入清理，且并非逐次通过上传接口生成。
- 65,535 项上限另有一次隔离实测：合成 65,533 个不同附件及相应记录，构造 63,258,334 字节的 ZIP；目标实例项目预算设为 64 MiB（记录用量 34,750,941 字节，超过默认 20 MiB）。实际恢复生成 65,533 个文件，再导出后记录和全部附件内容一致；从构造至完成约 219 秒，未计入清理。包采用较短的合成字段以满足 64 MiB 请求体限制，不代表所有同条目数的历史包都能导入，也不是对真实项目、其他设备或默认预算的性能承诺。
- 使用内部 `buildApp` 选项将项目预算提高到 80 MiB 的隔离样本中，13 个各 5 MiB 的不同附件通过实际上传，曾产生 68,172,701 字节的导出包，恢复因 64 MiB 请求体限制返回 413。现已在 ZIP 组装前按 STORE 格式计算大小并拒绝超限导出；同类样本的集成测试验证失败状态、不可下载且无 ZIP 残留。恢复接口边界测试确认超过 64 MiB 一字节返回 413；另将真实导出包的清单用 JSON 空格填充至恰好 64 MiB，恢复并再次导出后核对了项目、变更、附件记录和附件内容。该样本是合成边界包，并非由实际大项目直接导出的 64 MiB 包。默认 20 MiB 项目预算不受该大项目样本影响。
- 导出取消或超过截止时间后，会在当前附件读取返回时停止继续读取，并在创建输出文件后、写入前再次核对状态；无法抢占已经在操作系统中执行的单次读取或正在同步执行的 ZIP 组装。
- 恢复在数据库激活前清理暂存；注入暂存目录删除失败时，项目不激活、本次新建附件被回滚，重试可成功。普通错误时会清理本次创建的暂存与未激活附件，并保留原有同地址文件；清理操作自身持续失败或进程被强制终止时尚无自动清理保证，可能遗留未引用文件。
- 恢复时按审阅回执动作核对资源类型、包内归属及请求指纹对应的变更；伪造回执指向包外项目或包内其他变更会在激活前被拒绝。该校验不能证明不可信恢复包中的业务内容真实。

## 能力边界（明确未提供）

- 执行记录、证据、目标候选和验收建议的 agent 写入要求有效写会话授权，并在事务中再次校验代次和绑定；接管或释放后的旧授权不能重放写请求。读取历史回执不需要写授权。交接快照、审阅预览和附件上传的工具调用也要求有效写会话；附件核对会话所属项目，异步核对后在事务中再次校验。审阅阶段可以开始或由用户接管会话。Web 用户操作仍按本机用户权限执行；会话不限制外部进程直接修改文件。
- 实现目标的新确认按事务中持久化的每变更顺序选取，不依赖时间戳。v16 数据库升级或恢复 v16 包时，只有一个已确认目标的变更保留该目标；多个已确认目标的先后无法可靠还原，审阅不会选取其中任何一个作为当前目标。工作台可将用户选定的历史目标重新生成为带来源标识的新候选，并由用户再次确认；历史目标、决定与回执保留。已验收状态不因迁移自动改写。
- v16、v17 数据库升级 v18 前会备份原数据库；旧版程序不能读取 v18。新版接受结构和引用校验通过的 v16、v17、v18 包。历史处置没有可推断的目标时保留记录但不解除失败阻塞。新增字段增加记录占用，接近容量上限的历史项目迁移后可能无法新增记录；恢复时仍按本机预算检查并原子拒绝超限包。回退要求升级前的应用和包含附件的配套备份；升级后的新记录不会自动合并。
- 工作区观察列表和审阅中的最近观察按数据库插入顺序读取。新导出保留这一顺序；此前导出的恢复包按随机 ID 排列观察，恢复后可能将旧观察显示为最近，且无法从包内可靠还原真实顺序。恢复旧包后应重新绑定工作区并重新观察，不应将历史列表首项当成最近实际状态。
- 同一仓库登记多个工作区时，CLI `target add` 以当前写会话绑定的工作区核对目标，显式 `--workspace` 必须与其一致；工作台用户操作不指定时仍按插入顺序选择。旧包恢复后需重绑定工作区，核对目录和仓库身份再确认目标。
- 工作台确认目标时提交所见工作区绑定版本；如果读取后被重绑，服务端拒绝确认并提示重新核对。为兼容旧 API 客户端，不传绑定版本的确认请求不具备读取与确认之间的此项保护；确认请求开始后的并发重绑仍会由事务复核拒绝。
- 新执行、证据、目标、建议和审阅决定按已验证的用户会话判定操作者；若同时携带用户会话与工具令牌，沿用权限检查的用户优先规则。旧版本可能把携带额外 Authorization 头的用户操作记为工具，历史记录未被追溯更改。
- 恢复项目激活与持久回执同事务提交；相同请求标识和包内容可重放原回执，包内容不同会冲突。工作台可查询未决请求回执；未找到可能是仍在执行，不能当作失败。指针依赖浏览器站点存储，旧版本已完成的恢复无法追溯生成回执；回执不包含在项目恢复包内。
- 失败处置绑定确认时的目标，更换目标后须重新处置。旧记录未保存目标时保留可查，但不解除当前失败阻塞；展示历史并不替代用户检查与确认。
- 项目列表展示已登记目录和进行中的变更数量；目录检查受时间及进程级两项并发限制，超时或无法读取时显示待核对，目录存在也不代表仓库身份已验证。超时不会取消已发往操作系统的检查，若文件系统长期无响应，最多两个检查仍可能占用线程；线程池配置很小或其他负载较高时仍可能影响其他文件操作。恢复后存在历史工作区但尚未重新绑定的项目会持续显示提示；原本没有工作区的恢复项目与新建空项目无法仅凭现有记录区分，统一提示尚未登记工作区。
- 工作台记录与受管理附件不是源码备份；恢复包不含源码、未提交差异正文、依赖、运行环境或任何凭据。
- 未提供：分包导出、历史清理、跨变更冲突自动检测、多项目合并恢复。
- 凭据边界：登录口令与浏览器会话随进程重启失效；写会话授权不经包导出。
- 未发布：npm 发布、GitHub Release、自动推送均不在本版动作内。
