# 首版优先个人续做、冻结版本验收与数据可携带

用户在 grill-with-docs 第一轮明确接受以下三个建议，替代此前详细设计中的对应默认方案。原设计同时承担个人上下文接续、多人责任移交及每次操作的 Git 持久化，增加了尚未证明必要的首版成本。

1. **先解决发起人自己的跨会话、跨工具续做。** 多人责任交接后置，不把账号协作、接手请求、拒绝、改派或责任回执作为首版必需能力。第二个人可以帮助验证材料是否可理解，但不以完成多人责任移交流程作为首版交付门槛。
2. **验收针对明确冻结的规格与实现版本。** 已验收不表示已合并、已发布或与当前上游完全一致。上游刷新状态独立表达；不得仅因远端暂时不可达或出现尚未采用的新版本而否定已具备本地完整依据的冻结版本验收。实际采用新规格或实现目标后，仍需判断证据适用性，不自动继承旧通过。
3. **硬要求是可导出、可恢复，不是每次操作写 Git。** 原生规格继续保留在已有 Git 工作流中；撤销专用记录分支、每次操作提交和 Git / 数据库双写作为首版强制架构的要求。实际存储方式、导出内容、恢复范围和运行位置待后续轮次确定，此决定不等于已经选定数据库权威或某种备份格式。

本决定形成时，主文档曾暂存旧草案供后续收敛。第四轮结束后，[方案总览](../01-项目愿景与方案总览.md)和[首版详细设计](../02-首版详细设计.md)已统一重写；与本决定冲突的旧条款不再作为实施依据。这里保留当时的取舍理由，不代表所有具体实现选择都由用户逐项确认。
