# 本机续做、Markdown 交接与用户确认关键决定

用户在 grill-with-docs 第二轮接受 Q4—Q7 的推荐，在 [ADR-0001](0001-v01-continuation-acceptance-portability.md)的范围内进一步确定日常使用方式。

1. **首版本机运行。** 浏览器打开本地 Web，薄 CLI 连接同一个本地服务，优先验证用户的 Windows 开发环境。远程托管与多设备实时同步后置；换机先通过导出、恢复处理，其包含哪些数据仍待明确。
2. **未提交时也可以保存进度并续做。** 记录当前依据、工作区状态、已做事项和下一步；这属于开发中的草稿记录，不自动成为正式验收证据。正式验收仍要求规格与实现版本可固定、可核对。此决定没有承诺自动备份或恢复未提交代码，具体恢复边界待下一轮确定。
3. **通过 Markdown 材料与薄 CLI 交接。** 新会话显式读取交接材料并检查实际项目文件；agent 在结束或暂停时整理和回写进度。首版不依赖自动抓取不同工具的聊天历史，也不因材料已生成就认定新会话已正确理解。具体保存触发点及工具接入约定待细化。
4. **用户确认关键决定。** agent 可以记录进度、提交测试证据、整理缺口和提出验收建议；范围 / 基线变更、风险豁免和最终验收由用户确认。普通开发步骤不逐条请示，agent 的建议不能被记录成用户已经批准。

本决定替代旧详细设计中以多人登录服务为前提的首版入口，以及“必须先提交才能保存开发进度”的潜在解释；不放宽正式验收的版本约束。本轮当时尚未确定的恢复与写入边界已在后续 ADR 中补齐，持久化方式由整合后的详细设计给出工程选择。

本次仅更新设计决定和术语，未编写代码、安装依赖或执行 Git 提交、推送。

后续决定：[ADR-0003](0003-recovery-single-writer-checkpoints.md)已明确只恢复工作台记录与受管理附件、同一变更单个活跃写会话，以及关键节点保存；以上段落中的对应待定项以该后续决定为准。
