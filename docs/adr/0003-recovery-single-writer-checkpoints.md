# 恢复工作台数据、单个活跃写会话与关键节点保存

用户在 grill-with-docs 第三轮接受 Q8—Q10 的推荐，明确个人续做所能承诺的恢复范围与写入规则。

1. **恢复范围为工作台记录和受管理附件。** 代码由 Git 或独立工作区备份迁移，恢复工作台后重新绑定项目目录并核对实际文件。导出包不承诺包含未提交代码、新建源码文件、依赖或运行环境；原工作目录丢失时，不能仅靠工作台导出包找回未提交改动。外部证据链接可以随记录导出，但链接目标不等于已备份附件。
2. **同一变更只允许一个活跃写会话。** 切换工具时显式接续，旧会话不能覆盖新会话进度。不同变更可以并行开发，但并行改代码应使用独立工作区。这是工作台对记录写入的约束，不宣称能阻止外部工具直接修改源码。
3. **在关键节点保存进度。** 约定 agent 在完成可交接的小步骤、形成关键测试结果、准备暂停或切换工具时调用薄 CLI 保存；用户也可以随时要求手动保存。首版不自动录制全部聊天。异常中断后，只保证读取最近一次成功保存的记录，新会话仍须检查实际文件并识别记录之后的改动。

这些决定补全 [ADR-0002](0002-local-draft-continuation-human-decisions.md)中恢复边界、并行写入与保存时机的待定项；不把未提交的进度记录升级为正式验收证据，也不改变 [ADR-0001](0001-v01-continuation-acceptance-portability.md)中的冻结版本验收边界。

写会话标识、失效与接续校验、导出格式、文件指纹和保存失败后的重试由详细设计落实，不能用后台全量聊天采集或自动代码回滚替代以上约定。本轮仅沉淀决定，未编写产品代码或执行提交、推送。
