# 统一记录写入、批量确认与普通 Markdown 优先

用户在 grill-with-docs 第四轮接受 Q11—Q13 的推荐，并要求据所有已确认决定统一重写主方案与详细设计，暂不编写代码。

1. **工作台记录统一通过 Web / CLI 修改。** 交接 Markdown 是由记录生成的输出，直接修改它不会自动回写；原生规格 Markdown 仍按正常开发方式编辑。采用单一权威记录，避免文件与界面成为相互覆盖的两个编辑源。
2. **允许集中审阅后的批量验收与证据复用。** 用户选定明确的一组条件，一次确认；系统仍为每项保存独立决定。缺少证据、失败未处理或版本无法核对的项目不得混入批量通过；风险豁免单独明确确认，不随批量通过隐式批准。
3. **首版普通 Markdown 优先，Spec Kit 自动导入后置。** 用户明确选择规格依据和验收条件，先验证工具 A 保存进度、中断后工具 B 核对文件并继续开发、回收证据、用户验收、导出和恢复这一真实小闭环。专用解析器不是首版前提。

与 [ADR-0001](0001-v01-continuation-acceptance-portability.md)、[ADR-0002](0002-local-draft-continuation-human-decisions.md)、[ADR-0003](0003-recovery-single-writer-checkpoints.md)共同构成当前产品约束。整合后的 [主方案](../01-项目愿景与方案总览.md)和 [详细设计](../02-首版详细设计.md)是当前阅读入口；历史 ADR 中的“待后续明确”需结合后续决定阅读，不再表示主文档仍保留旧草案。
