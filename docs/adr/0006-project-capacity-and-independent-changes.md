# 项目容量预算与独立变更验收

用户在 grill-with-docs 中确认 Q17、Q18，要求同步文档并继续核查，暂不写代码、不提交或推送。

1. **Q17：优先保证已保存数据仍在完整导出与恢复的容量边界内。** 首版采用明确的项目容量预算，接近上限提前提示，会突破可导出范围的新增写入明确拒绝；已有记录仍可读取和导出。不自动删除历史，不通过漏掉记录或附件来缩小恢复包。具体额度通过样本验证调整，分包与历史清理后置。代价是触顶后需在扩容能力验证通过后才能继续新增，而非允许无限保存、到导出时才发现无法带走。
2. **Q18：不同变更独立冻结与验收。** 首版不做跨变更冲突检测，不维护全项目唯一最新规格；共享规格条目 ID 不意味着自动同步基线。各变更验收仅针对各自的冻结依据与实现目标，集成冲突由正常 Git 流程和人工审阅处理。真实使用反复出现遗漏时，再考虑基于显式共享条目 ID 的提示，不提前增加语义冲突分析。

容量预算保证的是格式与规模可支持，不保证磁盘、文件完整性或运行环境永不出错；实际导出、恢复仍按既有失败校验执行。详细规则与验证责任分别落实到详细设计、技术选型和实施计划。
