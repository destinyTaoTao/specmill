# M1 真实双工具续做样本记录（2026-11-15）

对应 [K08：生成固定交接并完成真实续做（M1）](https://github.com/destinyTaoTao/specmill/issues/9) 的真实样本要求。样本使用编译后的本机服务（dist-server，端口 43240）与编译后的 CLI（dist-cli），数据目录与样本仓库均为临时目录，样本内容不含个人项目数据。

## 样本设置

- 任务：临时 Git 仓库中的"罗马数字双向转换"小项目（src/roman.js + tests/roman.test.js，Node 内置 test）。
- 变更目标：toRoman/fromRoman 全部测试通过，边界与非法输入有明确错误；验收条件四条（node --test 全部通过、0/负数/4000 抛 RangeError、非法字符串抛 SyntaxError、1..3999 往返一致）。
- 工具 A 与工具 B 都是运行在本机的独立编码代理：各自拥有独立上下文，B 未接触 A 的对话或思考记录，仅凭固定交接材料（HANDOFF.md 文件）与工作台 CLI 查询续做。这是同机双代理样本，不是两个不同厂商产品的样本；该局限在下一条目中如实记录。

## 工具 A（移交方）

- 基线状态：2 过 / 3 失败（fromRoman 未实现，toRoman 缺边界）。
- A 的实际工作：实现 fromRoman 基础解析（大写归一、字母表校验、减法求值），保留两处已知失败：toRoman 边界缺失、fromRoman 组合合法性校验缺失。
- CLI 流程：session start → workspace observe（选定 src/roman.js、tests/roman.test.js 采集摘要）→ checkpoint save（如实记录已完成/已知失败/未验证/下一步）→ handoff create → handoff show --file HANDOFF.md → session release。
- 耗时：从会话开始到释放完成 **92 秒**（含全部 CLI 调用与测试运行）。
- 产出：保存点 7790146d（记录版本 3）、快照 77139f6f、材料 HANDOFF.md、变更版本 4（释放后）。

## 工具 B（续做方）

- B 拿到的全部信息：交接材料文件路径、项目目录、CLI 命令清单（不含任何 A 的工作细节）。
- B 的核对：按材料"续做须知"查询工作台最新状态，发现变更版本已从材料捕获的版本 3 推进到 4（材料过时点被正确识别）；通过 `workspace list --project` 找到工作区 ID（材料未含该 ID）；核对真实目录与 git 状态与材料观察一致。
- B 的实际工作：toRoman 补齐 0/负数/≥4000 的 RangeError；fromRoman 补组合合法性校验（以规范形式回比实现，拒绝 IIII、IC、VV、IIX 等）；测试 5 过 / 0 失败；未修改测试文件；未提交 git；未回滚 A 的任何修改。
- CLI 流程：session start（基于查询到的最新版本）→ workspace observe → checkpoint save（如实记录）→ session release。
- 耗时：从开始到保存点提交完成 **200 秒**（子代理总计运行约 255 秒，含报告）。
- 产出：保存点 60c8ca1e（记录版本 6）、变更版本 7、activeSession 为 null。

## M1 验收对照

| 要求 | 结果 |
| --- | --- |
| B 能说清目标、做到哪里、缺口、下一步 | 达成：B 报告复述了目标、A 的进度与失败、剩余缺口并按下一步完成 |
| 实际续做成功（新保存点） | 达成：B 保存点记录版本 6，测试 5/5 通过 |
| 不复制完整原聊天即可续做 | 达成：B 无 A 的对话上下文，报告"无需补充"任何人为上下文 |
| A 的过期写回被拒 | 达成：A 的授权在释放后再次尝试 checkpoint save，返回 409 SESSION_EXPIRED |
| 文件未被回滚 | 达成：git status 与开始时一致，仅 A/B 各自的合法修改 |
| 保存后新增源码改动可识别 | 达成（另行覆盖）：continuation 对比接口与 e2e 覆盖保存后新增文件/修改的场景，提示未保存工作且不回滚 |

## 记录的补充上下文与成本

- B 报告**无需人工补充上下文**；材料未含工作区 ID 一项通过工作台查询自行解决（提示：交接材料可考虑加入工作区 ID，作为后续小改进）。
- 遗留的唯一非代码事项与上下文无关：验收依据仍是未确认草案修订，需用户确认冻结后才能正式验收（符合首版设计中"用户确认关键决定"的边界）。
- 成本记录：A 移交流程 92 秒，B 续做 200 秒；B 消耗约 0.7M token。相比"复制完整原聊天"的方式，材料 + 工作台查询的路径信息密度足够，无重复解释成本。
- 与"不用工作台"的对照未做量化对比（属 K18 的容量与价值实测范围），本记录不声称效率结论。

## 样本局限（如实记录）

- A、B 为同一模型在不同上下文中的两个代理，非两个异构工具；跨工具适配（其他产品接入 CLI）仍是后续 K17/K18 的验证范围。
- 样本任务规模小（约 60 行代码）；更大任务下材料的充分性需更多样本支撑，不能由本样本外推。
- 样本期间的写会话、保存点、快照均未宣称构成正式验收或恢复能力（M2/M3 未完成）。
