# SpecMill v0.1 最小闭环实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成“普通 Markdown 建立变更 → 工具 A 保存未提交进度 → 工具 B 核对并续做 → 用户按冻结版本批量验收 → 导出并独立恢复”的本机闭环。

**Architecture:** 单个本地应用服务统一处理 Web 和薄 CLI 的请求，SQLite 保存记录，独立目录保存不可变附件。外部工具负责开发与测试；工作台只读观察项目、保存依据与决定，不执行 agent 或改写源码。

**Tech Stack:** TypeScript、Node.js 24 LTS、npm、Fastify 5、TypeBox、React 19／Vite、better-sqlite3、Git CLI、Vitest、Playwright；细节见[首版技术选型](../../03-首版技术选型.md)。

**Spec:** [主方案 v0.4](../../01-项目愿景与方案总览.md)、[详细设计 v0.2](../../02-首版详细设计.md)、[领域词汇表](../../../GLOSSARY.md)。

文档版本 v0.1，2026-11-14。本文件是未来实施任务清单，所有复选框均未执行；本轮不创建工程骨架、代码、测试或配置文件。以下路径、接口和命令是计划，不是对现有实现的描述。

## Global Constraints

- 同一变更最多一个活跃写会话。读取不限于该会话；工作台无法禁止外部进程直接改源码。
- 进度可在未提交、测试失败时保存。保存成功、代码已备份、验收通过是三个不同事实。
- agent 可以记进度、提交证据与建议；采用范围变更、接受豁免和最终验收由用户确认。
- Web／CLI 共用工作台记录与业务规则；生成的交接 Markdown 不接受编辑回写。
- 批量确认仍保存每项独立决定，不能把未知、缺失或失败的项目隐式视为通过。
- 工作台恢复只覆盖记录与受管理附件。没有另行备份的源码修改不能从保存点找回。
- “已验收”绑定冻结版本；不以联网、刷新远端、合并或发布为完成前提。
- 未来实施使用技术选型中的版本策略和限额；不得静默增加多人、远程托管、Spec Kit 导入或源码恢复范围。
- 不自动执行 Git 初始化、提交、推送或发布。任务完成先验收并更新清单；真实项目 Git 操作依用户授权，测试仓库仅在隔离临时目录中构造。
- 本轮授权仅为编写计划，不因计划中出现实现命令或技能名称而开始实施。

## Review Focus

以下五类边界纳入指定任务，不留给最后“综合测试”：

1. Windows 中文／空格路径、大小写别名和 worktree：身份判断不能重复占用或绑定错误目录；T2、T3。
2. 保存成功但响应丢失、进程中断和磁盘写入失败：重复请求不重做，失败不伪报成功；T3、T5、T7、T8。
3. 未可信 Markdown、日志和附件：只当数据展示，不能执行 HTML、脚本或命令，不能把正文当授权；T2、T4、T5。
4. 预览之后的旧会话写回、新失败和目标变更：拒绝旧写入和过期确认，但不误挡尚未采用修改之外的冻结版本验收；T3、T6。
5. 损坏／恶意恢复包、相同项目 ID 和恢复后的旧凭据：激活之前拒绝，不污染现有数据；T8。

## 3. 跨任务契约

接口是应用层用例名，不要求照搬成 RPC。HTTP 使用 /api/v1；所有可变实体带 version，变更视图统一称 ChangeView，含阶段、周期、当前基线／目标、最近保存点与 writer 状态。

- Command<T>：requestId、expectedVersion、payload；创建新实体时 expectedVersion 为 null。已有实体修改必须给版本；agent 变更写入另带 writerSessionId 与 generation。
- Receipt：requestId、resourceId、recordVersion、committedAt。重试同一键且内容相同返回相同回执；键相同内容不同拒绝。
- Actor：由服务凭据解析为 user 或 agent，并关联能力；不得由请求正文指定权限身份。
- CheckpointInput：目标／依据引用、done、failures、unverified、blockers、nextSteps、observationId；Draft 引用固定草案修订，baselineId 可空。
- ReviewContext：changeId、cycle、baselineId、implementationTargetId；条件另带 criterionRevisionId。ReviewPreview 还包含 recordVersion、选中项、证据引用、排除原因及 previewId。
- ReviewSelection：每项包含 criterionRevisionId、evidenceIds、mode（new／reuse）；reuse 必须有 reuseReason。豁免不在该集合中，走独立接口。
- ErrorBody：code、message、requestId、可选 currentVersion；HTTP 与 CLI 退出码按技术选型第 5 节。
- RecoveryManifest：formatVersion=1、schemaVersion、projectId、exportedAt、records 摘要及附件的名称／长度／摘要清单；不包含本机凭据。

上述类型随责任任务添加到对应 contracts 文件。禁止两端独立手写同名不同义类型；公共请求不能接受任意 SQL、Git 命令或文件系统路径作为通用执行入口。

未来 T1 统一定义 npm 脚本：typecheck、lint、test（Vitest run）、test:e2e（Playwright test）、build、dev、start、cli。本计划的验证命令只能在这些脚本和测试文件实际创建后执行；预期退出码为 0，指定用例被实际执行，无 skip 冒充通过。
