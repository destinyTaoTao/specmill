# 写会话、失败处置与恢复回执实施计划

用户已授权按安全可靠、兼容历史数据的方向修复；所有迁移及测试使用隔离数据目录，不提交或推送。

1. schema v18：备份旧数据库；失败处置增加可空目标引用，旧记录保持未知而不自动解除当前目标的阻塞；恢复回执在激活事务中持久化，不计入项目预算或恢复包。
2. 恢复器支持 v16、v17 和 v18，逐版本校验字段并保守转换；新处置必须绑定目标、预览和确认期间复核版本与上下文。覆盖切换目标、历史记录、旧包、伪造引用、容量与回滚。
3. 恢复按请求 ID 与包摘要幂等重放，回执与项目激活同事务；冲突请求、并发、重启及响应丢失均有确定行为；工作台可按请求 ID 查询已提交结果，不存储恢复包正文。
4. agent 写执行、证据、目标候选和建议必须携带当前会话授权；业务事务内重校验代次、变更和工作区，CLI 使用授权文件；覆盖接管、重启、并发、旧请求和用户操作。
5. 更新使用与兼容说明，执行相关及全量测试、构建、浏览器和安装验证；检查 diff 与遗留风险。
