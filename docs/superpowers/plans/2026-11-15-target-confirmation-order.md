# 目标确认顺序实施计划

> 按用户确认实施；不提交、推送或修改真实工作台数据。

**目标：** 用户确认目标的先后不依赖墙上时钟；旧数据库和 v16 恢复包保守处理不可还原的历史顺序。

**方案：** 在目标记录中增加仅在新确认时写入的每变更顺序。旧数据仅有一个已确认目标时保留其适用性；多个目标时不猜测，用户通过新候选重新确认。原目标、确认时间和回执保留；新候选获得新 ID，避免旧决定自动复用。所有数据转换、导出恢复与确认写入都在现有事务边界内。

1. 在隔离测试中复现同毫秒、时钟回拨、历史多目标不确定和旧包恢复；核对旧确认回执及已验收历史不被改写。
2. 增加带备份的 v17 迁移；确认顺序在事务中分配，审阅读取按顺序选择并在不确定时拒绝新验收；保留现有请求幂等和绑定版本校验。
3. 恢复器显式支持 v16 转换及 v17 包校验，确保归属、唯一顺序、项目额度和失败回滚；旧程序无法读取新数据，回退使用迁移前备份。
4. 工作台提供对历史目标重新生成候选的入口和明确提示，再由用户确认；覆盖失败、重试、刷新、键盘与真实浏览器流程。
5. 更新使用文档；运行相关集成测试、构建、静态检查、浏览器流程和安装包验证，并检查最终 diff。
